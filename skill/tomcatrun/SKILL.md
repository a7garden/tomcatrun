# tomcatrun — 에이전트가 톰캣을 다룬다

tomcatrun 실행기(0.32.0 이상)가 켜져 있으면 제어 창구로 부른다. 사람이 실행기 화면에서 보는 상태와 에이전트가 보는 것이 같다.
이 안내서는 tomcatrun {{VERSION}} 이 깔았다 (실행기 「설정 › 에이전트 스킬」). 실행기를 새 판으로 올리면 켤 때 함께 바뀐다.

```bash
TR="{{MJS}}"   # 셸 상태가 다음 명령으로 이어지지 않으면 명령마다 앞에 붙인다
node "$TR" status
```

결과는 사람이 읽는 짧은 글이다. `--json` 을 붙이면 받은 JSON 을 그대로 낸다. 실패하면 표준 오류에 까닭과 종료 코드 1 (실행기가 꺼져 있으면 2).

## 명령

| 하는 일 | 명령 |
| - | - |
| 서버마다 상태 · 마지막 컴파일 · 재시작해야 반영되는 것 | `node "$TR" status` |
| 고친 자바 · 매퍼가 들어가기를 기다려 결과 보기 | `node "$TR" settle <서버>` — 최근 60초 안의 컴파일만 이번 결과로 본다 (`--since 초`) |
| 재시작 · 시작 · 중지 (끝날 때까지 기다린다) | `node "$TR" restart <서버>` · `start` · `stop` (`--timeout 초` · `--no-wait`) |
| 이미 켜는 중인 서버를 끝까지 기다리기 | `node "$TR" wait <서버>` |
| 손으로 컴파일 | `node "$TR" compile <서버> [--full]` — 보통은 저장하면 실행기가 알아서 한다 |
| 실행기 알림 (컴파일 오류 · 반영 결과 · 재시작 사유) | `node "$TR" log <서버> --app [--errors]` |
| 톰캣 로그 끝 · 오류 줄만 · 직전 기동분 | `node "$TR" log <서버> [--lines N]` · `--errors` · `--prev` |
| 서버 점검 (jar · 포트 · 이클립스와 다른 곳) | `node "$TR" checks <서버>` |
| SVN 작업복사본 상태 · 잠금 | `node "$TR" svn <서버>` |
| SVN 저장소에서 받을 커밋 · 내 변경과 겹치는 파일 | `node "$TR" svn-incoming <서버>` |
| Git 상태 · 받을 커밋 (마지막 fetch 기준) | `node "$TR" git <서버>` · `node "$TR" git-incoming <서버>` |
| 꺼진 실행기 켜기 | `node "$TR" launch` |

`<서버>` 는 번호(0부터) · id · 이름 어느 것이든 된다. 처음에는 `node "$TR" status` 로 어느 서버가 어느 프로젝트인지 본다 — 고친 파일이 든 프로젝트의 서버를 고른다.

기동은 1~2분 걸린다. `restart` · `start` 는 Bash 도구의 `timeout` 을 600000 으로 주거나 `run_in_background` 로 돌린다.

## 고친 뒤 무엇을 하나

| 고친 것 | 할 일 |
| - | - |
| JSP · JS · CSS · 이미지 | 없다. 저장하면 바로 들어간다 |
| 자바 | `node "$TR" settle <서버>` — 컴파일 · 클래스 교체 · Spring 빈 반영(컨트롤러는 7~10초)을 기다린다. 컴파일이 실패하면 오류 줄을 보고 고친다. 「재시작해야 반영」이 나오면 재시작한다 |
| 매퍼 XML | `node "$TR" settle <서버>` — 앱이 매퍼 묶음을 다시 읽는다 (2~3초) |
| Spring 설정 XML · web.xml · properties · pom.xml | 기동 때만 읽는다 → 재시작 |

`settle` 이 끝나기 전에 브라우저로 확인하면 옛 동작이 보인다.

## 지키는 것

1. **재시작은 필요할 때만, 하면 보고에 적는다.** 사용자가 그 서버로 화면을 시험하는 중일 수 있다. 내 변경이 「재시작해야 반영」에 올랐거나 기동 때만 읽는 파일을 고쳤을 때, 또는 사용자가 시켰을 때만 한다. 실행기 화면에도 「에이전트가 … 재시작했습니다」가 남는다.
2. **내 작업과 상관없는 서버는 건드리지 않는다.** 꺼져 있던 서버를 켜거나 다른 프로젝트의 서버를 끄지 않는다 (사용자가 시키면 한다).
3. **사용자가 버전 관리 작업 중이면 기다린다.** `status` 에 「버전 관리 작업을 하는 중」이 보이면 그동안 재시작 · 중지하지 않는다.
4. **버전 관리는 조회만 한다.** 창구에 Commit · Update · Revert · Cleanup 은 없다. 그런 일이 필요하면 실행할 명령이나 누를 곳을 사용자에게 알린다. SVN 쓰기 명령을 셸로 직접 돌리지도 않는다.
5. **기동이 실패하면 고치기 전에 원인을 읽는다.** `restart` 가 실패하면 실행기 알림과 톰캣 로그의 오류 줄을 함께 낸다. 모자라면 `node "$TR" log <서버> --errors` · `--lines 400`. 포트가 막혔다(`Address already in use`)면 IDE 에 같은 서버가 떠 있을 수 있다 — 사용자에게 알린다.
6. **실행기가 꺼져 있으면** (`실행기가 꺼져 있습니다`) `node "$TR" launch` 로 켠다. 켜도 톰캣은 저절로 뜨지 않는다. 실행 파일을 못 찾거나 계속 꺼져 있다고 나오면 실행기가 0.32.0 보다 낮을 수 있다 — 사용자에게 켜거나 업데이트해 달라고 알린다.
7. **`settle` 이 「이번에 컴파일한 것이 없습니다」라고 하면** 반영됐다고 보고하지 않는다. 자동 컴파일이 꺼졌으면 `compile` 로 손수 하고, 저장한 지 오래됐으면 `--since` 를 늘린다.

## 창구

실행기가 켜질 때 `127.0.0.1` 의 빈 포트에 열고 포트 · 토큰을 `%LOCALAPPDATA%\tomcatrun\ctl.json` 에 적는다. `tomcatrun.mjs` 가 그 파일을 읽어 `X-Tomcatrun-Token` 머리로 보낸다.
`curl` 로 직접 부를 때의 경로 목록은 tomcatrun 저장소 `app/src/ctl.rs` 머리말에 있다.
